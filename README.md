# 주간 ETF 리포트 자동화 (MVP v2)

3단계 &ldquo;MVP 실제로 만들어보기&rdquo;의 결과물입니다. 매주 사람이 하나하나 찾아보던 ETF·종목 가격·수익률을,
명령어 한 줄로 자동 조회 → 계산 → 문서 저장까지 처리해주는 최소 기능 버전입니다.

> 이 폴더는 이번 자동화 실습을 위해 새로 만든 작업 폴더입니다. 원본 자료가 있는
> `DAY1숙제_업무자동화` 폴더와는 별개이며, 그 폴더의 파일은 전혀 건드리지 않습니다.

**v2에서 바뀐 점** (v1 대비): 대상 종목 3개 → **100개**, 가격 시점 2개(최근·1주전) →
**5개**(최근·1주전·1달전·3개월전·1년전), 수익률 1개 → **4개**(1주·1달·3개월·1년),
그리고 이번 주 상승·하락 top5에 자동으로 번호를 매기고 **원인 분석**을 덧붙이는
`notes` 기능이 추가되었습니다.

---

## 1. 이게 뭐 하는 물건인가 (쉽게 설명)

컴퓨터에게 "관심 있는 종목·ETF 100개의 최근/1주/1달/3개월/1년 가격이 어떻게 됐는지 알아서
표로 정리해줘"라고 시킬 수 있는 자동화 도구입니다. 지금은 사람이 명령어 한 줄을 직접
입력해야 시작되지만(수동 트리거), 일단 시작만 하면 그 뒤로는 사람 손을 거치지 않고
아래 순서를 전부 알아서 처리합니다.

1. `code/config.json`에 적힌 100개 종목·ETF 목록을 읽는다
2. 종목마다 야후 파이낸스에서 **최근 2년치 공개 시세 데이터를 조회**한다
   (읽기 전용 — 사내 자료를 외부로 보내는 동작 없음)
3. 최근종가를 기준으로 1주 전·1달 전·3개월 전·1년 전 종가를 찾아 수익률(%)을 계산한다
4. 이번 주(1주 수익률) 기준 **상승 top5·하락 top5**를 규칙에 따라 자동으로 골라
   `notes` 번호(1~10)를 붙인다
5. 결과를 `output/weekly-etf-insight-오늘날짜.md` 파일로 저장한다
6. 실행 과정을 `output/logs/` 폴더에 기록으로 남긴다

**아직 하지 않는 것** (MVP 범위 밖 — 2단계 설계서의 &ldquo;B. 나중에 추가할 기능&rdquo;에 해당)
- 매주 자동으로 실행되는 것 (지금은 사람이 직접 실행해야 함)
- ETFCheck·FunETF를 통한 수치 교차검증
- 레버리지 ETF 별도 표시, 방송 스크립트 변환

### ★ 스크립트가 절대로 못 하는 것 — "notes 분석"

`notes` **번호**(어떤 종목이 top5에 드는지)는 순위 계산이라 스크립트가 자동으로 정할 수
있습니다. 하지만 **"왜 그렇게 움직였는지" 분석 글**은 스크립트가 쓸 수 없습니다 — 계산이
아니라 조사·판단이 필요한 일이기 때문입니다.

그래서 실제 작업 순서는 이렇게 나뉩니다.

1. **스크립트 실행** → notes 번호까지만 자동으로 붙은 리포트가 나온다 (분석 내용은 빈 칸)
2. **사람(또는 Claude가 웹 검색)** → notes 번호가 붙은 종목만 골라 뉴스를 찾아보고,
   리포트 파일의 "주요 분석" 항목을 직접 채워 넣는다

이 부분을 완전히 자동화하려면 스크립트 안에 LLM·웹검색 API를 연결해야 하는데, 이는
MVP 범위를 넘어서는 훨씬 큰 작업입니다 (2단계 설계서 &ldquo;C. 완성형 시스템&rdquo; 참고).

## 2. 폴더 구조 · 각 파일의 역할

```
주간ETF리포트_자동화\
├─ README.md                        ← 이 문서
├─ code\
│  ├─ config.json                   ← 조회할 종목 100개 목록 (여기만 고치면 종목 변경 가능)
│  └─ weekly_report_mvp.js          ← 실제 작업을 수행하는 프로그램 본체
└─ output\                          ← 실행 결과가 저장되는 곳 (실행할 때마다 새로 생성됨)
   ├─ weekly-etf-insight-YYYY-MM-DD.md   ← 최종 리포트 (notes 분석은 이후 수동으로 보강)
   └─ logs\
      └─ 실행로그-YYYY-MM-DD.txt         ← 실행 기록 (성공/부분성공/실패, 시각, 사유)
```

| 파일 | 역할 |
|---|---|
| `code/config.json` | 조회할 종목·ETF 100개 목록. 종목마다 `테마` 항목에 &ldquo;어느 산출물에서 왜 뽑혔는지&rdquo;를 적어뒀습니다. 종목을 바꾸고 싶으면 코드는 건드리지 말고 이 파일만 수정 |
| `code/weekly_report_mvp.js` | 데이터 조회(5개 시점) → 수익률 계산(4개 기간) → notes 순위 계산 → 문서 작성 → 저장을 수행 |
| `output/weekly-etf-insight-*.md` | 매 실행마다 새로 생기는 결과물. notes 번호까지는 자동, "주요 분석" 글은 별도로 보강 |
| `output/logs/실행로그-*.txt` | 매 실행마다 새로 생기는 실행 기록 (100종목 각각의 성공/실패 사유) |

### `config.json` 종목 선정 기준

01.리포트.pdf에 실제 지시·산출물로 언급된 종목·테마(반도체, 빅테크, 커버드콜, 헬스케어,
금융주, 코스닥, 우주항공, 연금 등)를 우선 반영했습니다. 02.결과물.pdf는 이미지 PDF라 이번
세션에서 직접 열람하지 못해, 01번 PDF의 서술을 근거로 선정했습니다. 국내 ETF는 웹 검색으로
종목코드를 확인한 것을 우선 포함했고, 확인하지 못한 일부(코드 옆에 &ldquo;코드 확인
필요&rdquo;라고 표시된 항목)는 다음 실행 때 실패로 표시될 수 있습니다 — 이 역시 &ldquo;틀린
값을 지어내지 않고 확인 필요로 표시한다&rdquo;는 원칙에 따른 것입니다.

## 3. 실행 방법 (그대로 복사해서 붙여넣기)

PowerShell 창에서 아래 한 줄을 실행하면 됩니다. 어느 폴더에 있든 상관없이 이 명령어만
실행하면 알아서 이 프로젝트 폴더를 찾아 동작합니다.

```
node "C:\Users\jaewi\OneDrive\01. 업무자료\057. 업라이즈(HEYBIT)\95. AI교육\주간ETF리포트_자동화\code\weekly_report_mvp.js"
```

**100종목을 순서대로 조회하기 때문에 1~3분 정도 걸립니다.** 화면에는 종목별로
`[성공] (12/100) ...` 형태의 진행 상황이 순서대로 출력됩니다.

실행이 끝나면 아래와 비슷한 마지막 줄이 나타납니다.

```
[시각] 리포트 저장 완료: ...\output\weekly-etf-insight-YYYY-MM-DD.md
[시각] === 실행 종료: 정상 100건 / 부분 확인 필요 0건 / 실패 0건 ===
```

## 4. 결과가 제대로 나왔는지 확인하는 방법

1. `output` 폴더를 열어 오늘 날짜가 붙은 `weekly-etf-insight-YYYY-MM-DD.md` 파일을
   메모장이나 워드, VS Code 등으로 열어봅니다.
2. 맨 위 &ldquo;종목별 현황(작성기준일 : ...)&rdquo; 표에서 각 종목 옆 &ldquo;상태&rdquo;
   칸을 확인합니다.
   - **정상** → 5개 시점 가격이 모두 정상 조회됨
   - **⚠️ 부분 확인 필요** → 일부 기간(예: 1년 전)만 데이터가 부족함 (예: 최근 상장된 종목)
   - **⚠️ 실패** → 그 종목 자체를 아예 조회하지 못함
3. `notes` 칸에 1~10 숫자가 있는 종목은 이번 주 상승·하락 top5에 해당하며, 표 아래
   &ldquo;주요 분석&rdquo; 항목에서 같은 번호로 원인 설명을 확인할 수 있습니다.
4. `output/logs` 폴더의 실행로그 파일을 열면, 100종목 각각 언제 무엇이 성공/실패했는지
   한 줄씩 남아있습니다.

## 5. 자주 생길 수 있는 오류와 대처법

| 증상 | 원인 / 대처 |
|---|---|
| `'node'는 내부 또는 외부 명령... 아닙니다` | Node.js가 인식되지 않음 — 터미널을 새로 열거나, 컴퓨터를 재시작한 뒤 다시 시도 |
| 특정 종목이 &ldquo;⚠️ 부분 확인 필요&rdquo; | 그 종목의 상장일이 최근이라 1년 전(또는 3개월 전) 데이터가 없는 경우가 많습니다. 표에 어떤 기간이 부족한지 함께 표시됩니다 |
| 특정 종목이 &ldquo;⚠️ 실패&rdquo; | 티커 오타(예: 국내 ETF에 `.KS`/`.KQ` 누락)이거나 상장폐지·코드 변경. `output/logs`의 실행로그에서 정확한 실패 사유를 확인할 수 있습니다 |
| 전체 종목이 다 실패함 | 인터넷 연결 문제이거나, 회사 네트워크가 야후 파이낸스 접속을 막고 있을 가능성. 다른 인터넷 사이트는 잘 열리는지 먼저 확인해보세요 |
| `config.json` 형식이 깨짐(오타·괄호 누락 등) | &ldquo;설정 파일 읽기 실패&rdquo; 로그만 남기고 프로그램이 안전하게 멈춥니다. 다른 파일은 전혀 손상되지 않습니다 |
| notes 옆 "주요 분석"이 비어있음 | 정상입니다 — 스크립트를 막 실행한 직후에는 원인 분석 글이 비어있습니다. 이 부분은 사람(또는 Claude에게 요청)이 웹 검색으로 채워 넣어야 합니다 |

## 6. 다음에 추가하면 좋은 기능

   (Windows 작업 스케줄러와 연결)
2. **notes 분석 자동화** — 지금은 사람이 매번 웹 검색으로 채워 넣는 &ldquo;주요
   분석&rdquo; 부분을, 스크립트가 검색 API·LLM과 직접 연동해 초안까지 자동으로 쓰게 만들기
3. **레버리지 ETF 별도 표시 + ETFCheck 교차검증** — 2단계 설계서에 남아있던 원래 계획

## 안전 원칙 (지켜진 것)

- 원본 폴더(`DAY1숙제_업무자동화`)의 파일은 전혀 읽거나 수정하지 않았습니다.
- 모든 결과물은 이 폴더(`주간ETF리포트_자동화`) 안의 `output/`에만 새로 생성됩니다.
- 외부로 사내 자료를 **보내는** 기능은 없습니다 — 야후 파이낸스에서 공개 시세를,
  뉴스 검색에서 공개 기사를 **받아오기**만 합니다.
- 조회에 실패했거나 데이터가 부족한 항목은 숫자를 지어내지 않고 항상
  &ldquo;확인 필요&rdquo;·&ldquo;실패&rdquo;로 표시합니다.
